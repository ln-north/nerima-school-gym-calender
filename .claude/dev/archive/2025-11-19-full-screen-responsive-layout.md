## タスクの概要

現在のUIを全画面アプリに変更し、PC/Tablet（横幅が広い画面）とSP（スマートフォン）で最適化されたレスポンシブレイアウトを実装。PC/Tabletではサイドバー（320px固定）+ メインエリアの2カラム、SPでは上部ヘッダー/フィルター + メインエリアの1カラムレイアウトに変更し、全画面アプリ化を実現。

## 具体的に行った内容

### 変更されたもの

- **レイアウト構造**: 1カラム → 2カラム（PC/Tablet）/1カラム（SP）のレスポンシブ対応
- **ヘッダーデザイン**: 「個人開放カレンダー」+ 「練馬区」バッジ（PC/Tablet: text-xl、SP: text-lg）、コンパクト化
- **フィルターUI**: PC/Tabletは縦並びリスト形式（チェックボックス）、SPはドロップダウン形式（「スポーツ（選択数）▽」「学校（選択数）▽」）
- **カレンダー表示**: カード装飾（bg-white, rounded-lg, shadow-lg, p-4）を削除し、全面表示化
- **カレンダーツールバー**: 「← 2025年11月 →」形式の矢印ナビゲーションに変更、ビュー切り替えボタンを削除
- **スポーツの並び順**: ラケットスポーツ → テニス系 → バレー系 → バスケ系 → その他球技 → その他に整理

### 追加されたもの

- **全画面レイアウト対応**: html/body に h-screen を適用し、画面全体を使用
- **レスポンシブ2カラムレイアウト**: PC/Tablet でサイドバー320px固定 + メインエリアの構成
- **サイドバーフィルターUI**: 縦並びリスト形式（チェックボックス）、学校とスポーツ両方を直接表示
- **ドロップダウンフィルターUI**: SP向け、「スポーツ（選択数）▽」「学校（選択数）▽」形式
- **スポーツアイコン**: テニス系🎾、バレー系🏐、バスケ系🏀、フットサル⚽、初心者卓球教室🏓
- **カスタムツールバーコンポーネント**: react-big-calendar用、矢印ナビゲーション形式を実現
- **CLAUDE.md**: 開発ガイドライン、npm run build禁止の注意事項、トラブルシューティング

### 削除されたもの

- **カレンダーのカード装飾**: bg-white, rounded-lg, shadow-lg, p-4 を削除し、全画面表示に統一
- **ビュー切り替えボタン**: 「日」「予定」などのビュー切り替えを削除、月表示のみに統一
- **「もっと見る」ボタン**: PC/Tabletではすべてのスポーツを直接表示するため削除

## 検討事項と判断に至った経緯

### 主要な技術的選択

- **Tailwind CSS の lg: ブレークポイント（1024px）を使用**: PC/Tablet と SP を明確に分離し、レスポンシブ対応を実現
- **Flexbox レイアウト（flex flex-col lg:flex-row）**: 2カラム/1カラムを容易に切り替え、コードの可読性を維持
- **variant prop による UI 切り替え**: Filter コンポーネントで PC/SP 向けUIを条件分岐し、コードの重複を避ける
- **react-big-calendar の高さを h-full に変更**: 全画面レイアウトに対応し、親要素の高さに合わせて表示

### 議論した内容

**フィルターUI の形式**:
- チップ形式 vs ドロップダウン vs モーダルベース
  - PC/Tablet: 縦並びリスト形式（スクロール不要、すべて表示）
  - SP: ドロップダウン形式（画面幅を節約、タップで展開）

**カレンダーのカード装飾**:
- 残す vs 削除
  - 削除を選択（全画面アプリとして没入感を高める）

**スクロール処理**:
- ページ全体のスクロール vs 独立したスクロール
  - サイドバーとメインエリアを独立してスクロール可能に（overflow-y-auto）

## 技術的に特筆すべき事項

### 実装上の工夫

- **Filter コンポーネントの variant prop**: 同じコンポーネントで PC/SP のUIを切り替え、コードの重複を避ける設計
- **カスタムツールバーコンポーネント**: react-big-calendar のデフォルトツールバーを置き換え、矢印ナビゲーション形式を実現
- **スポーツの並び順整理**: 関連性のあるスポーツをグループ化（ラケットスポーツ、テニス系、バレー系、バスケ系）、ユーザーの探しやすさを向上
- **スポーツアイコンの追加**: 視覚的な識別性を向上、UI の楽しさを追加（テニス🎾、バレー🏐、バスケ🏀、フットサル⚽、卓球🏓）

### 発見した問題・制約

- **react-big-calendar の高さ設定**: 親要素の高さが必要なため、h-full と flex-1 を適切に使用する必要がある
- **モバイルブラウザのアドレスバー**: h-screen は viewport の高さ（100vh）だが、アドレスバー分が引かれる場合がある
  - 現状は h-screen で対応（必要に応じて h-dvh に変更可能、Tailwind CSS v3.4 以降でサポート）
- **スクロール挙動**: サイドバーとメインエリアを独立してスクロールさせるため、overflow-hidden と overflow-y-auto を適切に配置

## アーキテクチャへの影響

- **レイアウト構造の全面変更**: 1カラム → 2カラム/1カラムのレスポンシブ対応、全画面アプリ化
- **URL 状態管理の維持**: 既存の ?schools=...&sports=... クエリパラメーターは変更なし、フィルター変更時の挙動も維持
- **コンポーネントの責務**: Filter コンポーネントが PC/SP のUI切り替えを担当、variant prop で制御
- **スタイルの一貫性**: Tailwind CSS のブレークポイント（lg:）を統一的に使用し、レスポンシブ対応を一元管理
- **スクロール処理**: ページ全体のスクロールを無効化し、サイドバーとメインエリアを独立してスクロール可能に変更
